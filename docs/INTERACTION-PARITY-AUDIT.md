# Interaction parity audit — every control in the prototype, opened

> **Updated in PR D (2026-10-11).** The audit itself was read-only (2026-10-07). This copy is the record: every row that was bucket 3 is now bucket 1 with its decision (D-495 to D-499, `docs/DECISIONS.md`), and the four documents it found out of step are corrected (see the end of "Documents that no longer match").

**Read-only. Nothing was changed.** Product: `staging` at `7ad0f15`. Prototype: `docs/visual-reference/prototype-2026-09-27/Main.dc.html` and `Auth.dc.html` (the source files, not screenshots). Date: 2026-10-07.

## What this closes

Earlier parity pairs compared pages at rest. This audit opens every interactive element in the prototype and lists what it reveals: popovers, dropdown and "…" menus, dialogs, drawers, tabs, inline editors, toasts, empty states, error states, hover and selected states, and keyboard handling. It covers the notifications list and the notes popover. Each handler was traced into the prototype's logic script to the markup its state reveals. The product counterpart was found in the code on `staging`, or reported as "not found".

## Totals

**548 elements opened**: 311 same, 116 different, 121 missing. Of the 237 that are different or missing:

- **235 in bucket 1**: decided, with the decision cited — the 165 the audit found decided, and the 70 that were bucket 3, decided in PR D (D-495 to D-499);
- **2 in bucket 2**: blocked on data that does not exist yet;
- **0 in bucket 3**. (At the audit, 70 rows were bucket 3: not decided anywhere.)

## How each row is bucketed

- **Bucket 1 needs a decision number.** That is either:
  - an owner decision (D-number);
  - or an element listed as "left out" in `docs/UI-FIDELITY-CONTRACT.md` §4.3, §4.5 or §6. D-468 makes that list the record: an element that needs data or a feature that does not exist is left out _and listed_.
- **The new decisions of item 3:**
  - "Search anything" is **D-485** (deferred);
  - every "View as" element is **D-486** (cancelled).
- **The Studio popover.** "When should it go out?" (Studio S10–S14) is bucket 1. It is queued for PR C under the owner's 2026-10-07 instruction on `ContentItem.proposedLocalTime`.
- **Items listed only in `docs/R4-PARITY-INVENTORY.md` are bucket 3**, marked "known (R4)". That inventory sizes "left out" items for the owner but records no decision. D-473 (3) names its "left out by owner decision" and "for want of data" items one by one, and only those count as decided. This rule was applied the same way to all three parts of the audit. Four rows changed because of it:
  - three campaign-form rows went from bucket 1 to bucket 3;
  - Notes "selecting a thread marks it read" went from bucket 1 to bucket 3.
- **Why bucket 2 is small.** Most elements that need missing data (connectors, analytics history, AI output) are already listed under D-468 as left out for want of data, so they are bucket 1 with that citation. Bucket 2 holds only the two rows with no such listing.
- **Size and API.** S/M/L is the effort of the gap alone. "API" means a new route under `apps/api` or `apps/dashboard/src/app/api`; a new server action is not a new API path.

## Keyboard shortcuts

The prototype has **no global shortcut**:

- "⌘K" exists only as the search button's title text (Main L151);
- the only keys it handles are Esc and Enter inside the search box, and Esc during a calendar drag.

The product's own keyboard support is product-only and is not counted: arrow-key tabs and menus, the calendar drag, and the @-mention list.

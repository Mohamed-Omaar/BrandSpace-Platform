# Round 4 — Parity inventory (Gate 1: Steps 1–2)

Authority: `docs/visual-reference/prototype-2026-09-27/` (D-468). This document is the Step 2
inventory of every customer-facing route, tab, dialog, drawer, popover, menu and major state,
with the status of each under the round's strict definition of **PORTED**.

**PORTED** means all twelve requirements hold: the visual structure, computed dimensions,
typography and spacing, controls and interactions, loading/empty/error states,
dialog/drawer/popover/menu states, English checked, Arabic checked, RTL, collapsed rail where
it applies, passing automated tests, and no parity defect found in the browser. A screen whose
main happy-path screenshot matches is **not** PORTED for that reason alone.

- **PARTLY**: the prototype's composition is in place but at least one requirement is still
  open. The open item is named in the row.
- **NOT PORTED**: missing, or substantially different from the prototype.
- **BLOCKED**: cannot be finished without a schema change, a new API path or a prohibited
  change.

Discovery used four sources:

1. The prototype's own markup: screens, `role="dialog"`, `role="menu"`, `role="listbox"`,
   `aside`, and the `*Open` state flags in `Main.dc.html`.
2. The product's route tree: every `page.tsx` under `apps/dashboard/src/app/[locale]`.
3. The rail and Settings navigation (`NAV`, `SETTINGS_NAV_ROUTES`).
4. Runtime inspection: a prototype/product pair at 1440×900 for every row marked † below, plus
   the census and specs in the Evidence column.

"Before" is each row's status at `ebefbab`, the merge of #68, judged under the same strict
definition.

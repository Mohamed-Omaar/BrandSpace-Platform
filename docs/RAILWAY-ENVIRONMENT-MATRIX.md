# BrandSpace on Railway — Environment Variable Matrix

> **الملخص التنفيذي بالعربية**
>
> جدول مرجعي لكل متغير بيئي يحتاجه النشر على Railway: اسمه بالضبط، والخدمات التي تحتاجه، ومصدره، وهل هو سرّي، وشكله — **دون أي قيمة حقيقية**.
> المتغيرات مصنّفة إلى سبع فئات: ما تولّده Railway، والمراجع بين الخدمات، والأسرار التي ننشئها، وإعدادات المالك، وبيانات المزوّدين المستقبلية، وما هو للتطوير فقط، وما هو **ممنوع في الإنتاج**.

**No value in this document is real.** Every example shows a _format_, never a
secret. Read `docs/RAILWAY-DEPLOYMENT.md` first for the reasoning.

**Source of truth:** `packages/shared/src/env.ts` (the Zod schema and
`assertProductionSafety`), plus every direct `process.env` read in `apps/*/src`
and `packages/*/src`. This matrix was generated from those, not from memory. If
the two disagree, the code is right and this file is stale.

## Classes

| Class | Meaning                                                  |
| :---: | -------------------------------------------------------- |
| **A** | Generated by Railway — injected into the service         |
| **B** | Reference to another Railway resource                    |
| **C** | BrandSpace cryptographic secret — the owner generates it |
| **D** | Owner-supplied deployment setting — not secret           |
| **E** | Future external-provider credential — **none set today** |
| **F** | Development / test only                                  |
| **G** | **Forbidden in production** — the parser throws          |

Service column: `W` web · `D` dashboard · `A` admin · `P` api · `K` worker · `M` migration job

## A — Generated by Railway

| Variable                 | Services  | Secret | Required | Notes                                                                                                                                                      |
| ------------------------ | --------- | :----: | :------: | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PORT`                   | W D A P K |   no   |   yes    | **Set explicitly, not inherited.** Pinned to the port each app's `start` script already uses: 3000/3001/3002/3003/3004. `docs/RAILWAY-DEPLOYMENT.md` §1.2. |
| `RAILWAY_PRIVATE_DOMAIN` | all       |   no   |   auto   | Injected. Used via a reference to compose the Postgres host.                                                                                               |
| `RAILWAY_PUBLIC_DOMAIN`  | W D A P   |   no   |   auto   | Injected once a domain exists. Not read by application code.                                                                                               |
| `RAILWAY_ENVIRONMENT`    | all       |   no   |   auto   | Injected. Not read by application code — `APP_ENV` is what BrandSpace reads.                                                                               |

`RAILWAY_*` variables are Railway's own and are not part of the BrandSpace
contract. They are listed so nobody mistakes `RAILWAY_ENVIRONMENT` for `APP_ENV`.

## B — Railway resource references

| Variable                           | Services | Secret | Required | Source                                        | Format                                              |
| ---------------------------------- | -------- | :----: | :------: | --------------------------------------------- | --------------------------------------------------- |
| `REDIS_URL`                        | D A P K  |  yes   |   yes    | Reference → Redis service `REDIS_URL`         | `redis://default:<pw>@<host>.railway.internal:6379` |
| `BRANDSPACE_POSTGRES_PRIVATE_HOST` | K        |   no   |    no    | Reference → Postgres `RAILWAY_PRIVATE_DOMAIN` | `postgres-abc123.railway.internal`                  |

`REDIS_URL` is a reference, so the credential is never typed anywhere and
rotates with the service. `BRANDSPACE_POSTGRES_PRIVATE_HOST` is a convenience: it
is a hostname, not a credential, and it lets the three role URLs be composed
without opening the database credential. It is read by no application code.

**Railway's own Postgres `DATABASE_URL` is referenced by nothing.** See class C.

## C — BrandSpace cryptographic secrets

Every one is generated by the owner with `openssl rand -base64 48`, set as a
**sealed** Railway variable, and never written down in this repository.

| Variable                  | Services |       Required        | Must differ from          | Format                                                                                  | Production rule                                                                                                                                      |
| ------------------------- | -------- | :-------------------: | ------------------------- | --------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`            | D A P K  |        **yes**        | `DATABASE_PLATFORM_URL`   | `postgresql://brandspace_app:<pw>@<host>.railway.internal:5432/railway?sslmode=disable` | Must be the `brandspace_app` role. **Never Railway's provisioned credential** — it owns the tables, and RLS is not enforced against a table's owner. |
| `DATABASE_PLATFORM_URL`   | A P      |     yes for those     | `DATABASE_URL`            | same shape, role `brandspace_platform`                                                  | Parser **throws** in production if it equals `DATABASE_URL`.                                                                                         |
| `DATABASE_MIGRATION_URL`  | M        |       yes for M       | both of the above         | same shape, role `brandspace_migrator`                                                  | Set **only** on the migration job. A runtime service holding it can perform DDL.                                                                     |
| `CUSTOMER_SESSION_SECRET` | D        |        **yes**        | `PLATFORM_SESSION_SECRET` | ≥ 32 chars, base64                                                                      | Parser **throws** if the two session secrets match.                                                                                                  |
| `PLATFORM_SESSION_SECRET` | A        |       yes for A       | `CUSTOMER_SESSION_SECRET` | ≥ 32 chars, base64                                                                      | A customer session presented to Admin must be cryptographically unusable, not merely rejected by policy.                                             |
| `SECRET_VAULT_KEK`        | A P      | **yes in production** | the other two KEKs        | ≥ 32 chars, base64                                                                      | Platform secret vault (D-136).                                                                                                                       |
| `SOCIAL_TOKEN_VAULT_KEK`  | P K      | **yes in production** | the other two KEKs        | ≥ 32 chars, base64                                                                      | Customers' own social OAuth tokens (D-136).                                                                                                          |
| `CUSTOMER_MFA_VAULT_KEK`  | D P      | **yes in production** | the other two KEKs        | ≥ 32 chars, base64                                                                      | Customers' own MFA seeds, reachable from the login surface (D-206).                                                                                  |

### The rules the parser actually enforces

From `assertProductionSafety`, when either `NODE_ENV=production` or
`APP_ENV=production`:

- All three KEKs must be **present**, and all three must be **distinct**. Absent
  → _"required in production"_. Shared → _"Sharing one collapses three blast
  radii into one."_
- `CUSTOMER_SESSION_SECRET` ≠ `PLATFORM_SESSION_SECRET`.
- `DATABASE_PLATFORM_URL` ≠ `DATABASE_URL` when both are set.
- **No placeholder.** Any variable whose name matches `/SECRET|KEK|PASSWORD|KEY/i`
  is rejected if its value contains `change-me`, `placeholder`, `example`,
  `devonly`, `localhost`, `replace_with`, `ci-only` or `test-only`. A value
  copied from `.env.example` fails at boot, not at the first sign-in.

### Which process holds which key

Not every service gets every key. This is the blast-radius design, deployed.

| Key                      |  W  |  D  |  A  |  P  |  K  |
| ------------------------ | :-: | :-: | :-: | :-: | :-: |
| `SECRET_VAULT_KEK`       |  —  |  —  | ✅  | ✅  |  —  |
| `SOCIAL_TOKEN_VAULT_KEK` |  —  |  —  |  —  | ✅  | ✅  |
| `CUSTOMER_MFA_VAULT_KEK` |  —  | ✅  |  —  | ✅  |  —  |

The dashboard verifies a TOTP at sign-in and holds that key alone — a login
request must not be able to unwrap a platform provider credential. The worker
unwraps customer social tokens when publishing and holds that one alone.

## D — Owner-supplied settings

| Variable                    | Services  | Secret | Required | Format                                   | Production rule                                                                                                                  |
| --------------------------- | --------- | :----: | :------: | ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `NODE_ENV`                  | all       |   no   |   yes    | `production`                             | Every built Next.js app sets this. It is the build mode, **not** the deployment environment.                                     |
| `APP_ENV`                   | all       |   no   |   yes    | `production` \| `staging`                | **This** is the deployment environment (D-97). Drives every production guard.                                                    |
| `DATA_REGION`               | all       |   no   |   yes    | `eu-west`                                | Where the data actually is. See the residency note in the deployment doc §1.4.                                                   |
| `LOG_LEVEL`                 | all       |   no   |    no    | `info` in production, `debug` in staging | Default `info`.                                                                                                                  |
| `PUBLIC_WEB_URL`            | W D A P K |   no   | **yes**  | `https://www.example.com`                | **Must be https in production** — the parser throws on `http://`.                                                                |
| `DASHBOARD_URL`             | W D A P K |   no   |   yes    | `https://app.example.com`                |                                                                                                                                  |
| `ADMIN_URL`                 | D A P K   |   no   |   yes    | `https://admin.example.com`              |                                                                                                                                  |
| `API_URL`                   | D A P K   |   no   |   yes    | `https://api.example.com`                |                                                                                                                                  |
| `PUBLIC_API_BASE_URL`       | D A P K   |   no   | **yes**  | `https://api.example.com`                | **Must be https in production.** Every OAuth callback and webhook URL is built from it at request time.                          |
| `PUBLIC_DASHBOARD_BASE_URL` | D A P K   |   no   |   yes    | `https://app.example.com`                | Where customers are returned to.                                                                                                 |
| `BRANDSPACE_API_URL`        | D A       |   no   |   yes    | `http://api.railway.internal:3003`       | **Internal only.** `http://` is correct: Railway's private network is already WireGuard-encrypted.                               |
| `WORKER_PORT`               | K         |   no   |   yes    | `3004`                                   | The worker serves its liveness endpoint here, not on `PORT`. Set both to the same value or Railway's probe hits a closed socket. |
| `OTEL_SERVICE_NAME`         | all       |   no   |    no    | `brandspace`                             | Default `brandspace`.                                                                                                            |
| `BRANDSPACE_WEBFONTS`       | D A       |   no   |    no    | `google`                                 | Opt-in. Unset keeps rendering hermetic. Leave unset unless the owner wants Google-hosted fonts.                                  |

### The https constraint is a deployment-order constraint

`PUBLIC_WEB_URL` and `PUBLIC_API_BASE_URL` default to `http://localhost:…` and
production refuses `http://`. The API and worker call
`validateStartupConfiguration()` at boot and **throw** in production.

So these must hold real https origins before the first production boot can
succeed — which is why domain generation moves to step 9 of the deployment
order, before any service is expected to start.

## E — Future external-provider credentials

**None is set. None is required. None appears anywhere in this repository.**

Listed so nobody adds one prematurely, and so the smoke test can assert their
absence.

| Category       | Variables                                                                                                    | Where they will live                                                                           |
| -------------- | ------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| AI providers   | none                                                                                                         | Platform Admin → Integrations, encrypted in the secret vault                                   |
| Social apps    | none                                                                                                         | Platform Admin → Integrations                                                                  |
| Payments       | none                                                                                                         | Platform Admin → Integrations                                                                  |
| Email          | none                                                                                                         | Platform Admin → Integrations                                                                  |
| Object storage | `STORAGE_ENDPOINT`, `STORAGE_REGION`, `STORAGE_BUCKET`, `STORAGE_ACCESS_KEY_ID`, `STORAGE_SECRET_ACCESS_KEY` | **Declared in the schema, consumed by nothing.** No S3 adapter exists — deployment doc §6.     |
| Observability  | `OTEL_EXPORTER_OTLP_ENDPOINT`                                                                                | Optional. Unset means spans are created locally and nothing is exported; readiness reports it. |

Provider credentials entered through the Integrations Hub are written to the
secret vault via the Secret Service and referenced by configuration — they are
**not** Railway environment variables. `SECRET_VAULT_KEK` is what makes that
possible, which is why it is class C and they are class E.

## G — Forbidden in production

| Variable                     | What happens                                                                                                            |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `BILLING_DEV_WEBHOOK_SECRET` | `assertProductionSafety` **throws**: _"it belongs to the development payment adapter, which cannot run there (D-204)."_ |

Its only consumer is the development payment adapter, which production refuses.
Its presence means a production environment was assembled by copying a
development one — and the next thing copied might not be harmless.

**The smoke test checks for it explicitly.**
